# Плагины exteraGram

Два способа убрать из канала посты с файлами:

* [`delete_file_posts.plugin`](delete_file_posts.plugin) — автоматический: сам находит,
  показывает список, удаляет пачками. Описан ниже.
* [`select_all_files.plugin`](select_all_files.plugin) — ручной: пункт «Выделить все»
  во вкладке «Файлы», дальше штатная корзина Telegram. Описан [в конце](#выделить-все).

# Чистка постов с файлами — плагин exteraGram

Удаляет в канале **только посты с вложениями**, обязательно показывая список перед
удалением. Пост `#44` (`https://t.me/c/2053026588/44`) в белом списке — он не удалится.

Файл плагина: [`delete_file_posts.plugin`](delete_file_posts.plugin)

## Установка

1. Скачать `delete_file_posts.plugin`.
2. Отправить файл самому себе в «Избранное» (или в любой чат) в exteraGram.
3. Нажать на файл → **Установить плагин**.
4. Настройки → exteraGram → Плагины → «Чистка постов с файлами».

## Как пользоваться

Два способа запуска:

* меню канала (три точки в шапке чата) → **Чистка постов с файлами**;
* настройки плагина → **Показать, что будет удалено**.

Порядок всегда один:

```
сканирование → список найденного → подтверждение → удаление
```

Пока включён переключатель **«Только просмотр»** (он включён по умолчанию),
кнопки удаления в окне вообще нет — можно спокойно смотреть, что нашлось.
Чтобы разрешить удаление, выключите его в настройках и запустите проверку заново.

## Настройки

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| ID канала | `-1002053026588` | Плагин отказывается работать с любым другим чатом. Пусто — разрешён текущий открытый чат. |
| Не удалять посты | `44` | ID через запятую. Можно вставлять ссылки `t.me/c/2053026588/44`. |
| Режим поиска | Только файлы (документы) | Либо документы, либо + видео/аудио/GIF, либо любые вложения включая фото. |
| Как обходить канал | Авто | Авто: сначала быстрый поиск по вкладке «Файлы», и если он вернул ноль — полный обход истории. Можно принудительно выбрать один из способов. |
| Только просмотр | вкл | Кнопка удаления недоступна. |
| Двойное подтверждение | вкл | Перед удалением спрашивает ещё раз. |
| Список в «Избранное» | вкл | Полный перечень найденного уходит в Saved Messages. |

## Что именно попадает под удаление

* **Только файлы (документы)** — посты, где вложение является документом (в том числе
  архивы, pdf, apk и прочее). Фото, обычные видео и текстовые посты не трогаются.
* **Файлы, видео, аудио, GIF** — дополнительно видео, музыка, голосовые и гифки.
* **Любые вложения** — всё, где есть медиа, включая фото. Ссылки с превью и чистый
  текст не считаются вложением.

Посты без вложений не удаляются ни в одном режиме.

## Безопасность

* Сканирование и удаление разделены: удалить что-то без показанного списка нельзя.
* Плагин привязан к одному ID канала и откажется работать в другом чате.
* Белый список ID проверяется до формирования очереди на удаление.
* Полный список найденного дублируется в «Избранное» — окно показывает только
  первые 25 строк, отчёт содержит всё.
* Удаление идёт пачками по 100 сообщений с паузой; `FLOOD_WAIT` обрабатывается
  автоматически, неудавшиеся пачки перечисляются в итоговом отчёте.

**Удаление постов в канале необратимо.** Сначала прогоните в режиме просмотра.

## Если плагин пишет «Ничего не найдено»

Окно показывает диагностику: сколько сообщений вернул сервер, сколько отсеяно
без вложений, сколько по типу, какие типы вообще встретились и были ли ошибки
запросов. Там же кнопка **«Обойти всю историю»** — она переключает способ обхода
на полный проход по истории канала и сразу перезапускает сканирование.

Полный обход надёжнее (не зависит от индекса поиска на стороне Telegram), но
идёт дольше: страницами по 100 сообщений, с паузой.

## Технические детали

* Поиск: `messages.search` с фильтрами `inputMessagesFilterDocument` / `Video` /
  `Music` / `Voice` / `Gif` / `Empty`, постраничная выборка по 100.
* Запасной обход: `messages.getHistory` постранично с фильтрацией вложений на
  стороне плагина. Включается автоматически, если поиск ничего не вернул.
* Удаление: `channels.deleteMessages` для каналов и супергрупп,
  `messages.deleteMessages` c `revoke=true` для остальных чатов.
* Все запросы выполняются в фоновом потоке, UI обновляется через `run_on_ui_thread`.

# Выделить все

Файл плагина: [`select_all_files.plugin`](select_all_files.plugin)

Добавляет пункт **«Выделить все»** в меню канала (три точки сверху). Отмечает
разом все подгруженные элементы открытой вкладки общих медиа, дальше удаляете
штатной корзиной Telegram.

## Как пользоваться

1. Канал → вкладка **«Файлы»**.
2. Три точки сверху → **«Выделить все»**.
3. Плагин сам докручивает список, пока клиент не подгрузит нужное количество —
   это занимает несколько секунд, дождитесь уведомления.
4. Корзина.

## Ограничения, о которых стоит знать

* **Удаление пачкой ограничено сотней на стороне Telegram**, а не клиента. Поэтому
  настройка «Максимум за раз» по умолчанию равна 100: выделить больше можно, но
  часть при удалении просто не пройдёт.
* Элементы подгружаются по мере прокрутки. Плагин докручивает список за вас, но
  упирается в тот же лимит — дальше смысла грузить нет.
* Для «всё за раз, очередью» предназначен `delete_file_posts.plugin`: он берёт
  файлы через API, минуя UI, и удаляет пачками по 100 подряд.
* Плагин лезет во внутренние поля экрана общих медиа через рефлексию, поэтому
  может перестать работать после обновления exteraGram. Все ошибки видны в логах
  клиента с префиксом `[select_all_files]`.

## Настройки

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| Максимум за раз | `100` | Сколько элементов отметить за одно нажатие. |
| Докручивать список сам | вкл | Плагин прокручивает вкладку вниз, пока клиент не подгрузит нужное количество. |
| Обходить проверки клиента | выкл | Пишет выделение напрямую, минуя ограничения Telegram. Нужно, если обычный способ не сработал: зажмите любой файл вручную, потом жмите «Выделить все». Клиент к таким объёмам не рассчитан — возможны подвисания. |

## Как это работает

Плагин находит `SharedMediaLayout` текущего экрана, определяет активную вкладку
и список её сообщений, при нехватке элементов прокручивает `RecyclerView` вкладки
до тех пор, пока клиент подгружает новые, включает штатный режим выделения длинным нажатием по
первому элементу и дальше проходит по остальным штатным обработчиком клика.
Если внутренние методы клиента не нашлись (другая версия клиента), выделение
записывается напрямую в `selectedFiles` с обновлением адаптеров.
