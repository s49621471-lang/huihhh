# Плагины exteraGram

Два способа убрать из канала посты с файлами:

* [`delete_file_posts.plugin`](delete_file_posts.plugin) — автоматический: сам находит,
  показывает список, удаляет пачками. Описан ниже.
* [`select_all_files.plugin`](select_all_files.plugin) — ручной: пункт «Выделить все»
  во вкладке «Файлы», дальше штатная корзина Telegram. Описан [в конце](#выделить-все).

# Чистка постов с файлами — плагин exteraGram

Удаляет в канале **только посты с вложениями**, обязательно показывая список перед
удалением. Пост `#44` (`https://t.me/c/2053026588/44`) в белом списке — он не удалится.

Файл плагина: [`delete_file_posts.plugin`](delete_file_posts.plugin)

## Установка

1. Скачать `delete_file_posts.plugin`.
2. Отправить файл самому себе в «Избранное» (или в любой чат) в exteraGram.
3. Нажать на файл → **Установить плагин**.
4. Настройки → exteraGram → Плагины → «Чистка постов с файлами».

## Как пользоваться

Два способа запуска:

* меню канала (три точки в шапке чата) → **Чистка постов с файлами**;
* настройки плагина → **Показать, что будет удалено**.

Порядок всегда один:

```
сканирование → список найденного → подтверждение → удаление
```

Во время удаления видно полосу прогресса с процентами и счётчик
«удалено N из M · осталось K · не удалось L». В конце — итоговое окно с теми же
цифрами и кнопкой **«Проверить остаток»**, которая перезапускает сканирование и
показывает, что реально осталось в канале.

Пока включён переключатель **«Только просмотр»** (он включён по умолчанию),
кнопки удаления в окне вообще нет — можно спокойно смотреть, что нашлось.
Чтобы разрешить удаление, выключите его в настройках и запустите проверку заново.

## Настройки

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| ID канала | `-1002053026588` | Плагин отказывается работать с любым другим чатом. Пусто — разрешён текущий открытый чат. |
| Не удалять посты | `44` | ID через запятую. Можно вставлять ссылки `t.me/c/2053026588/44`. |
| Режим поиска | Только файлы (документы) | Либо документы, либо + видео/аудио/GIF, либо любые вложения включая фото. |
| Как обходить канал | Авто | Авто: сначала быстрый поиск по вкладке «Файлы», и если он вернул ноль — полный обход истории. Можно принудительно выбрать один из способов. |
| Только просмотр | вкл | Кнопка удаления недоступна. |
| Двойное подтверждение | вкл | Перед удалением спрашивает ещё раз. |
| Список в «Избранное» | вкл | Полный перечень найденного уходит в Saved Messages. |

## Что именно попадает под удаление

* **Только файлы (документы)** — посты, где вложение является документом (в том числе
  архивы, pdf, apk и прочее). Фото, обычные видео и текстовые посты не трогаются.
* **Файлы, видео, аудио, GIF** — дополнительно видео, музыка, голосовые и гифки.
* **Любые вложения** — всё, где есть медиа, включая фото. Ссылки с превью и чистый
  текст не считаются вложением.

Посты без вложений не удаляются ни в одном режиме.

## Безопасность

* Сканирование и удаление разделены: удалить что-то без показанного списка нельзя.
* Плагин привязан к одному ID канала и откажется работать в другом чате.
* Белый список ID проверяется до формирования очереди на удаление.
* Полный список найденного дублируется в «Избранное» — окно показывает только
  первые 25 строк, отчёт содержит всё.
* Удаление идёт пачками по 100 сообщений с паузой; `FLOOD_WAIT` обрабатывается
  автоматически, неудавшиеся пачки перечисляются в итоговом отчёте.

**Удаление постов в канале необратимо.** Сначала прогоните в режиме просмотра.

## Если плагин пишет «Ничего не найдено»

Окно показывает диагностику: сколько сообщений вернул сервер, сколько отсеяно
без вложений, сколько по типу, какие типы вообще встретились и были ли ошибки
запросов. Там же кнопка **«Обойти всю историю»** — она переключает способ обхода
на полный проход по истории канала и сразу перезапускает сканирование.

Полный обход надёжнее (не зависит от индекса поиска на стороне Telegram), но
идёт дольше: страницами по 100 сообщений, с паузой.

## Технические детали

* Поиск: `messages.search` с фильтрами `inputMessagesFilterDocument` / `Video` /
  `Music` / `Voice` / `Gif` / `Empty`, постраничная выборка по 100.
* Запасной обход: `messages.getHistory` постранично с фильтрацией вложений на
  стороне плагина. Включается автоматически, если поиск ничего не вернул.
* Удаление: `channels.deleteMessages` для каналов и супергрупп,
  `messages.deleteMessages` c `revoke=true` для остальных чатов.
* Все запросы выполняются в фоновом потоке, UI обновляется через `run_on_ui_thread`.

# Чистка файлов

Файл плагина: [`select_all_files.plugin`](select_all_files.plugin)

Кнопка **«Удалить все файлы»** в меню канала (три точки сверху). Работает в фоне:
клиентом можно пользоваться, пока идёт удаление. Прогресс и лог — в настройках
плагина.

## Как пользоваться

1. Канал → три точки → **«Удалить все файлы»**.
2. Плагин собирает список с сервера и показывает, сколько нашлось.
3. Подтверждаете — окно закрывается, работа уходит в фон.
4. Прогресс смотрите в настройках плагина: строка вида
   «Удалено 300 из 543 · осталось 243 · ошибок 0».

Прокручивать вкладку и что-либо выделять не нужно — список берётся с сервера
целиком, интерфейс в этом не участвует.

## Прогресс и лог

Настройки плагина показывают текущее состояние и дают:

* **Открыть лог** — построчный журнал с временем;
* **Скопировать лог** — весь журнал в буфер обмена;
* **Лог в «Избранное»** — отправляет журнал сообщением себе;
* **Очистить лог**;
* **Остановить** — появляется вместо «Открыть лог», пока идёт работа;
  останавливает после текущей пачки.

## Настройки

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| Что удалять | Файлы (документы) | Файлы, фото и видео, музыка, голосовые или GIF. |
| Не удалять посты | `44` | ID через запятую, можно ссылками. |
| Канал-источник | пусто | Для режима репостов. Пусто — определяется автоматически. |
| Не отвлекать уведомлениями | выкл | Отключает всплывающие подсказки, прогресс остаётся в настройках. |

## Кто сколько постил

Пункт **«Кто сколько постил»** обходит всю историю канала или чата и раскладывает
посты по авторам — все подряд, а не только с вложениями.

1. Канал или чат → три точки → **«Кто сколько постил»**.
2. Плагин читает историю (`messages.getHistory` постранично) и показывает список:
   `Имя @username · 123456789 — 340 постов (файлов 120)`.
3. Тап по строке → окно с разбивкой и кнопкой удалить **все** посты этого автора.

Полный список авторов пишется в лог, включая тех, кто не поместился в окно
(в окне первые 40). Оттуда его можно скопировать одной кнопкой.

Автор определяется по `from_id`; для постов от имени канала используется подпись
`post_author`, если она есть. Посты из белого списка в подсчёт не попадают.

## Репосты канала в чате обсуждений

В привязанной к каналу группе автоматически появляются копии постов канала —
вместе с файлами. Пункт **«Удалить репосты канала»** убирает только их, не трогая
то, что выкладывали участники.

1. Открыть чат обсуждений → три точки → **«Удалить репосты канала»**.
2. Плагин собирает посты с вложениями и делит их на пришедшие из канала и чужие.
3. В подтверждении видно оба числа: сколько удалит и сколько оставит.

Канал-источник определяется сам: сначала по привязке чата
(`ChatFull.linked_chat_id`), а если она не загружена — по содержимому, самый
частый источник среди пересланных постов. Можно задать вручную в поле
«Канал-источник».

Принадлежность поста определяется по `fwd_from` (`from_id`, `saved_from_peer`) и
по отправителю: автопосты канала в обсуждении приходят от имени самого канала.

## Вкладка показывает удалённые файлы

Такое остаётся от прошлых удалений: посты снесены на сервере, а локальный кэш
клиента об этом не узнал. Лечится кнопкой **«Починить вкладку «Файлы»»** в
настройках плагина — она сверяет показанное с сервером и убирает из кэша записи о
постах, которых там уже нет. Сервер при этом не трогается: удаление идёт с флагом
`cacheOnly`. После чистки перезайдите во вкладку.

То же предлагается автоматически, если «Удалить все файлы» не нашло ни одного
поста, — значит удалять уже нечего, и дело в кэше.

Само удаление идёт через `MessagesController.deleteMessages`, чтобы клиент сразу
чистил свою базу и новых призраков не появлялось. Если внутренний метод клиента не
нашёлся, плагин уходит на прямой `channels.deleteMessages` и пишет об этом в лог.

## Про id канала

Внутри клиента канал адресуется как `-channel_id` (например `-2053026588`), а
запись `-100…` из ссылок `t.me/c/…` и Bot API там невалидна — с ней запрос падает
на `CHAT_ID_INVALID`. Плагин приводит id к внутреннему виду, а если тот не
подошёл, автоматически пробует вторую запись и пишет в лог, какая сработала.

## Ручное выделение

В меню остался пункт **«Выделить все»** — отмечает загруженные элементы открытой
вкладки, дальше штатная корзина. Запасной путь: Telegram отмечает не больше сотни
за раз и только то, что подгружено прокруткой.
